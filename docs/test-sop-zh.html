1. 安装说明

immurok 共包含三个组件，正式安装由签名 + 公证的 .pkg 一次性完成：

安装路径组件
/Applications/immurok.app菜单栏主程序（GUI）
/usr/local/bin/imk命令行工具 imk
/usr/local/lib/pam/pam_immurok.soPAM 模块（sudo / 系统授权）

方式 A：使用 .pkg 安装包（推荐 / 终端用户）

  1. 双击 immurok-<版本>.pkg 启动安装器。
  2. 按提示一路"继续"，输入当前 Mac 管理员密码授权安装。
  3. 安装器的 postinstall 会自动把 pam_immurok 写入 /etc/pam.d/sudo_local 与 /etc/pam.d/authorization，并赋予 imk 可执行权限。
  4. 安装完成后，/Applications/immurok.app 即可启动。
Gatekeeper 提示：若 pkg 未经公证（开发自构建），首次打开会被拦截。可在"系统设置 → 隐私与安全性"中点击"仍要打开"。正式发布版本已 notarize + staple，不会出现此提示。

方式 B：源码构建（开发者）

cd app-macos
swift build -c release          # 产出 immurokApp 与 imk 两个可执行文件

# 一键构建 + 签名 + 部署到 /Applications
./build-deploy.sh -a -s

PAM 模块单独构建：

cd app-macos/pam
make
sudo cp pam_immurok.so /usr/local/lib/pam/

2. 首次启动配置

首次打开 /Applications/immurok.app 会自动弹出 3 步配置向导（Setup Wizard）。已完成的步骤会被自动跳过。

步骤 ① 欢迎页

介绍三大能力：锁屏解锁、sudo 授权、系统授权。点击"下一步"。

步骤 ② PAM 模块检查

  • 若 pam_immurok.so 已就位（pkg 安装会自动完成），向导显示"已安装"并放行。
  • 若未检测到，向导提示需要安装 PAM 组件包（见安装方式 B）。

步骤 ③ 辅助功能权限（必需）

键盘模拟（解锁时自动输入密码、Quick Fill 自动键入）依赖"辅助功能"权限。

  1. 向导引导打开"系统设置 → 隐私与安全性 → 辅助功能"。
  2. 在列表中找到 immurok 并打开开关（如无则点 + 手动添加）。
  3. 返回向导，状态变为"已授权"。

完成：配置解锁密码

  1. 点击状态栏 immurok 图标 → "打开设置窗口"。
  2. 进入"权限 / Permissions"标签页，点击"配置解锁密码"。
  3. 输入当前 Mac 登录密码并保存（密码加密存入 macOS 钥匙串 com.katsu.immurok，不写入磁盘明文）。
  4. 首次还会请求蓝牙权限，请允许。
完成向导后，建议确认"开机自启动"已开启（基于 SMAppService，无需手动配置 launchd）。此后才能进入下方各项功能测试，许多功能依赖已配对设备（见功能 1）。

3. 卸载说明

方式 A：App 内卸载（推荐）

App 内置了签名的卸载 pkg，会完整清理所有组件。运行后将依次：

  1. 结束正在运行的 immurok 进程。
  2. 从 /etc/pam.d/sudo_local 与 /etc/pam.d/authorization 移除 pam_immurok 配置行。
  3. 删除 /usr/local/lib/pam/pam_immurok.so 与 /usr/local/bin/imk。
  4. 删除 /Applications/immurok.app。
  5. 删除用户数据 ~/.immurok、钥匙串密码项与 UserDefaults，并清理 pkg 收据。

方式 B：手动卸载（开发者）

killall immurok 2>/dev/null
sudo rm -rf /Applications/immurok.app
sudo rm -f /usr/local/lib/pam/pam_immurok.so /usr/local/bin/imk
# 从 PAM 配置中移除 pam_immurok 行
sudo sed -i '' '/pam_immurok/d' /etc/pam.d/sudo_local /etc/pam.d/authorization
rm -rf ~/.immurok
security delete-generic-password -s "com.katsu.immurok" -a "unlock-password" 2>/dev/null
defaults delete com.immurok.app 2>/dev/null
验证卸载：卸载后执行 sudo -k; sudo true 应恢复为正常密码提示（不再走指纹）；which imk 应无输出。

4. 功能体验测试

以下每个小节包含：功能名称 · 简介 · 操作顺序 · 预期效果。请按顺序测试：功能 1（配对）、功能 2（指纹录入）、功能 3（密钥录入）是其余功能的前提——没有指纹无法触摸授权，没有 SSH key 无法做 SSH/git 签名。

功能 1 · 设备配对

BLEECDH P-256前置必做

简介配对分两个独立阶段：先在系统蓝牙设置里把设备当成一个蓝牙键盘连上 Mac（建立链路锚点），再在 App 内与设备做 ECDH P-256 密钥交换（协商共享密钥用于后续 HMAC 校验，确保指纹信号不可伪造）。两步都只需做一次。

阶段一系统蓝牙连接（类似连接蓝牙键盘）

  1. 确保设备已上电、处于蓝牙广播状态，Mac 蓝牙已开启。
  2. 打开"系统设置 → 蓝牙"，在列表中找到 immurok 设备。
  3. 点击"连接"，像连接蓝牙键盘一样完成系统级配对（如有配对码按提示确认）。

阶段二App 内密钥交换配对

  1. 打开 App 设置窗口 → "设备 / Device"标签页。
  2. 点击 App 上的"配对 / Pair"按钮。
  3. 在设备上按下物理按键确认，双方完成 ECDH 密钥交换。
预期效果阶段一完成后系统蓝牙显示"已连接"；阶段二完成后 App 内设备状态显示"已配对 / 已连接"，配对信息持久化保存。此后重启 App 会自动重连，状态栏图标显示已连接。

功能 2 · 指纹管理（录入 / 删除 / 重命名）

枚举值需与固件同步前置必做

简介在"指纹"标签页管理设备上的指纹。这是后续所有"触摸授权"类功能（解锁、sudo、系统授权、SSH 签名、Quick Fill）的前提——必须先录入至少一枚指纹。录入过程的状态机（等待 / 已采集 / 处理中 / 抬起手指）与固件 fingerprint.h 枚举值保持一致。

操作顺序

  1. 设置窗口 → "指纹 / Fingerprint"标签页。
  2. 点击"录入新指纹"，按界面提示多次按压同一手指，直到提示完成。
  3. 对已录入指纹点击"重命名"修改名称；点击"删除"移除。
预期效果录入过程显示实时进度（采集次数 / 抬起手指提示），完成后列表新增条目；重命名即时生效；删除后该指纹不再能解锁/授权。

功能 3 · 密钥与凭证管理（含 SSH key 录入 / 生成）

SSHAPITOTP/OTPSystemSSH/Quick Fill 前置

简介"密钥"标签页支持四类条目：System（系统密码）、SSH/Git 私钥、API 凭证、OTP/TOTP 密钥。机密存储在设备上，受指纹保护。在测试功能 7（SSH agent）做 ssh / git 操作之前，必须先在这里录入或生成 SSH key；在测试功能 8（Quick Fill）之前，必须先在这里存入 OTP 条目。

操作顺序

  1. 设置窗口 → "密钥 / Keys"标签页，选择类别（System / SSH&Git / API / OTP）。
  2. 录入 SSH key：切到 SSH/Git 类别，粘贴一段 OpenSSH 格式私钥（导入时校验格式，不支持加密私钥），保存。
  3. 设备端生成 SSH key：或点"在设备上生成"，由设备生成密钥对、私钥永不导出；生成后可复制公钥用于 ~/.ssh/authorized_keys 或 GitHub。
  4. OTP：输入 TOTP 密钥（base32）；API：输入名称与凭证。保存后在列表查看，可重命名或删除。
预期效果合法条目保存成功并出现在列表，SSH 条目可见对应公钥；非法 SSH 私钥（格式错误 / 加密 / 不支持的类型）给出明确错误提示，不会保存。

功能 4 · 锁屏解锁

键盘模拟需辅助功能权限

简介类似 TouchID 的息屏解锁。App 检测到锁屏状态后，设备发送 HMAC 签名的指纹匹配通知（0x21），App 校验通过即从钥匙串读取密码并用 CGEvent 模拟键入。

操作顺序

  1. 确认已配置解锁密码、已授予辅助功能权限、设备已连接、已录入指纹（功能 2）。
  2. 锁定屏幕（Ctrl+Cmd+Q）。
  3. 在设备指纹传感器上触摸已录入的手指。
预期效果App 自动在密码框输入登录密码并回车，屏幕解锁。指纹不匹配时无动作，密码不会被输入。

功能 5 · sudo 授权

PAMsudo_local

简介用指纹替代终端中输入 sudo 密码。sudo 触发 pam_immurok.so，PAM 模块通过 ~/.immurok/pam.sock 与 App 通信，App 请求指纹，匹配后回 OK。

操作顺序

  1. 设置窗口"权限"页确认 "sudo 授权"开关已开启。
  2. 终端执行 sudo -k 清除缓存，再执行 sudo true。
  3. 看到提示后在设备上触摸指纹。
预期效果无需输入密码，指纹匹配后 sudo 直接通过。关闭开关后恢复为系统默认密码提示。
⚠️ macOS 13.x（Ventura）用户注意：App 对 macOS 13.x 的 sudo 支持将在下一版本正式提供。/etc/pam.d/sudo_local 包含机制是 macOS 14（Sonoma）才引入的——13.x 系统不会自动加载 sudo_local，因此安装器写入的配置不会生效。若你当前是 13.x 用户，请按以下步骤手动开启 sudo 支持：
  1. 确认 PAM 模块已就位：ls /usr/local/lib/pam/pam_immurok.so。
  2. 备份原配置：sudo cp /etc/pam.d/sudo /etc/pam.d/sudo.bak。
  3. 把以下行加到 /etc/pam.d/sudo 的第一条 auth 规则之前（紧跟首行注释后）：
    auth     sufficient    /usr/local/lib/pam/pam_immurok.so
    例如：sudo sed -i '' '1a\'$'\n''auth sufficient /usr/local/lib/pam/pam_immurok.so' /etc/pam.d/sudo
  4. 另开一个终端窗口执行 sudo -k; sudo true 验证（保留当前窗口，万一配置出错可用它恢复 sudo cp /etc/pam.d/sudo.bak /etc/pam.d/sudo）。
升级到支持 13.x 的版本后，请移除这条手动添加的行，改用安装器自动配置。

功能 6 · 系统授权对话框

PAM authorizationGUI 弹窗

简介系统设置中需要"输入密码以解锁"的授权弹窗（如修改安全设置）也可走指纹，由 /etc/pam.d/authorization 接入。

操作顺序

  1. 确认"系统授权"开关已开启。
  2. 打开一个需要授权的系统设置（如点击锁形图标解锁某项设置）。
  3. 在弹出授权对话框时触摸指纹。
预期效果授权对话框被指纹通过并关闭，设置项解锁。
注意：本项目严禁操作 authorizationdb，仅通过 PAM authorization 接入。

功能 7 · SSH agent 签名

ssh-agent 协议设备端签名需先完成功能 3

简介App 实现 SSH agent 协议，把签名请求转发给设备，使用存储在设备上的私钥做 ECDSA 签名——私钥永不离开设备。前置：必须已在功能 3 录入或生成 SSH key。

操作顺序

  1. 确认已在功能 3 中导入或生成 SSH key。
  2. 设置窗口"权限"页开启 "SSH agent"，按提示设置 SSH_AUTH_SOCK 环境变量指向 App 的 socket。
  3. 终端执行 ssh-add -l 查看密钥；再执行一次 ssh 或 git push。
  4. 触发签名时在设备上触摸指纹。
预期效果ssh-add -l 列出设备上的公钥；连接 / push 在指纹确认后由设备完成签名并成功。

功能 8 · Quick Fill OTP 快捷填充

默认 Ctrl+\热键可自定义

简介在任意输入框按全局热键（默认 Ctrl+\，keyCode 42）弹出快捷面板，搜索并选择条目，指纹确认后自动键入当前 TOTP 验证码或所选机密。

操作顺序

  1. 先在功能 3 中存入至少一个 OTP 条目。
  2. 在网页/App 的验证码输入框中按 Ctrl+\。
  3. 在弹出面板中搜索并选中目标条目，在设备上触摸指纹确认。
预期效果面板按服务名筛选；指纹确认后当前 6 位 TOTP 自动键入到光标处。可在设置中修改热键。
首次启动提示：App 首次启动后热键可能暂不响应——需在 App 设置中重新设置（或重新确认）一次热键，或重启 App 后，Ctrl+\ 才会生效。

功能 9 · imk CLI 与 Agent 命令授权

CLIimk run --agent

简介imk 用于终端工作流：列出/读取设备上的机密、注入环境变量运行子进程。imk run --agent 会在命令执行前弹出授权浮层，覆盖那些本身不触发 PAM 的命令（如 git pull、npm install）。

操作顺序

  1. 快速测试：imk run --agent -- echo "hello world" —— 浮层弹出，触摸指纹后终端打印 hello world。
  2. 列出条目：imk list ssh / imk list otp / imk list api。
  3. 读取机密到 stdout：imk get imk://api/<name>。
  4. 注入并运行：imk run --env-file .env -- python deploy.py。
  5. Agent 授权：imk run --agent -- git push origin main，浮层弹出时触摸指纹。
预期效果list 输出条目名；get 输出机密值（交互式 TTY 带换行，管道/重定向为原始字节）；--agent 指纹通过返回 OK 后命令才执行，关闭浮层或 30s 超时则返回 REJECT 拒绝执行。

功能 10 · 在 AI agent 中安装并测试 imk skill

Claude Code 插件SKILL.md指纹门

简介让 AI agent（Claude Code / Codex / Cursor / Cline …）执行敏感命令（sudo、git push/ssh、读取 secret）时，自动用 imk run --agent -- 包装，从而弹出指纹授权门。规则与决策树来自独立的 imk-skill 仓库（skills/using-imk/SKILL.md）。

安装 · Claude Code作为插件安装

  1. 克隆 skill 仓库到插件目录：
    git clone https://github.com/immurok/imk-skill ~/.claude/plugins/imk-tools
  2. 重启 Claude Code（或重新加载插件），使其识别 using-imk skill。
  3. 确认 imk 已在 PATH 中：which imk 应输出 /usr/local/bin/imk。

安装 · 其他 agentCodex / Cursor / Cline 等

  1. 打开 imk-skill 仓库中的 skills/using-imk/SKILL.md。
  2. 把其内容粘贴进该 agent 的 rules / 指令文件（如 AGENTS.md、.cursorrules、Cline 的自定义指令等）。
  3. 保存后让 agent 重新读取规则。

测试 skill

  1. 确保 App 已运行、设备已配对、已录入指纹。
  2. 直接验证 CLI 门是否生效：imk run --agent -- echo "hello world" —— 浮层弹出，触摸指纹后打印 hello world。
  3. 在 agent 对话里指派一条敏感命令（例如让它执行 git push 或 sudo systemctl restart api），观察它是否自动用 imk run --agent -- 包装后再执行。
  4. 包装命令运行时，在设备上触摸指纹授权。
预期效果agent 对敏感命令主动套上 imk run --agent --；执行前弹出指纹授权门，指纹通过命令才继续，拒绝/超时则命令不执行。纯只读命令（ls/cat/git log）与用户手动输入的命令不会被包装。
完整决策树、踩坑列表与安装步骤详见 imk-skill 仓库：github.com/immurok/imk-skill（skills/using-imk/SKILL.md）。
