1. Installation

immurok ships three components, installed in one shot by a signed + notarized .pkg:

Install pathComponent
/Applications/immurok.appMenu bar app (GUI)
/usr/local/bin/imkimk CLI tool
/usr/local/lib/pam/pam_immurok.soPAM module (sudo / system auth)

Option A: .pkg installer (recommended / end users)

  1. Double-click immurok-<version>.pkg to launch the installer.
  2. Click through "Continue" and enter your Mac admin password to authorize.
  3. The installer's postinstall automatically wires pam_immurok into /etc/pam.d/sudo_local and /etc/pam.d/authorization, and makes imk executable.
  4. When done, launch /Applications/immurok.app.
Gatekeeper note: an un-notarized (self-built) pkg is blocked on first open — allow it via "System Settings → Privacy & Security → Open Anyway". Official releases are notarized + stapled and show no prompt.

Option B: build from source (developers)

cd app-macos
swift build -c release          # produces immurokApp and imk

# one-shot build + sign + deploy to /Applications
./build-deploy.sh -a -s

Build the PAM module separately:

cd app-macos/pam
make
sudo cp pam_immurok.so /usr/local/lib/pam/

2. First-launch setup

The first launch of /Applications/immurok.app opens a 3-step Setup Wizard. Already-completed steps are skipped automatically.

Step ① Welcome

Introduces the three capabilities: screen unlock, sudo auth, system auth. Click "Next".

Step ② PAM module check

  • If pam_immurok.so is present (the pkg does this), the wizard shows "Installed" and lets you continue.
  • If missing, the wizard tells you to install the PAM component (see Option B).

Step ③ Accessibility permission (required)

Keyboard simulation (typing the password at unlock, Quick Fill auto-type) needs the Accessibility permission.

  1. The wizard opens "System Settings → Privacy & Security → Accessibility".
  2. Find immurok in the list and toggle it on (use + to add it manually if absent).
  3. Return to the wizard; status flips to "Granted".

Finish: configure the unlock password

  1. Click the immurok status-bar icon → "Open Settings Window".
  2. Go to the Permissions tab and click "Configure unlock password".
  3. Enter your current Mac login password and save (stored encrypted in the macOS Keychain com.katsu.immurok, never written to disk in plaintext).
  4. Grant the Bluetooth permission when prompted on first run.
After the wizard, confirm "Launch at login" is enabled (backed by SMAppService, no manual launchd needed). Most features below require a paired device (Feature 1).

3. Uninstall

Option A: in-app uninstall (recommended)

The app embeds a signed uninstall pkg that fully cleans up every component. It will:

  1. Terminate the running immurok process.
  2. Remove the pam_immurok line from /etc/pam.d/sudo_local and /etc/pam.d/authorization.
  3. Delete /usr/local/lib/pam/pam_immurok.so and /usr/local/bin/imk.
  4. Delete /Applications/immurok.app.
  5. Remove user data ~/.immurok, the Keychain password item and UserDefaults, and forget pkg receipts.

Option B: manual uninstall (developers)

killall immurok 2>/dev/null
sudo rm -rf /Applications/immurok.app
sudo rm -f /usr/local/lib/pam/pam_immurok.so /usr/local/bin/imk
# remove the pam_immurok line from PAM config
sudo sed -i '' '/pam_immurok/d' /etc/pam.d/sudo_local /etc/pam.d/authorization
rm -rf ~/.immurok
security delete-generic-password -s "com.katsu.immurok" -a "unlock-password" 2>/dev/null
defaults delete com.immurok.app 2>/dev/null
Verify: after uninstall, sudo -k; sudo true should fall back to the normal password prompt (no fingerprint), and which imk should print nothing.

4. Feature walkthrough

Each subsection has: name · description · steps · expected result. Test in order: Feature 1 (pairing), Feature 2 (enroll a fingerprint) and Feature 3 (store keys) are prerequisites for the rest — you can't touch-authorize without an enrolled fingerprint, and you can't do SSH/git signing without an SSH key.

Feature 1 · Device pairing

BLEECDH P-256prerequisite

DescriptionPairing has two separate stages: first connect the device to the Mac in System Bluetooth Settings, just like pairing a Bluetooth keyboard (this is the link anchor); then, inside the app, do an ECDH P-256 key exchange with the device (deriving a shared key for HMAC verification so fingerprint signals can't be forged). Each step is done once.

Stage 1System Bluetooth connection (like pairing a Bluetooth keyboard)

  1. Power on the device and make sure it's advertising; ensure the Mac's Bluetooth is on.
  2. Open System Settings → Bluetooth and find the immurok device in the list.
  3. Click "Connect" and complete system-level pairing as you would for a Bluetooth keyboard (confirm the pairing code if prompted).

Stage 2In-app key-exchange pairing

  1. Open the app's Settings window → Device tab.
  2. Click the "Pair" button in the app.
  3. Press the physical button on the device to confirm; both sides complete the ECDH key exchange.
ExpectedAfter Stage 1, System Bluetooth shows "Connected"; after Stage 2, the app shows the device as "Paired / Connected" and persists the pairing data. The app then auto-reconnects on restart and the status-bar icon shows connected.

Feature 2 · Fingerprint management (enroll / delete / rename)

enum synced with firmwareprerequisite

DescriptionManage on-device fingerprints in the Fingerprint tab. This is a prerequisite for every touch-to-authorize feature that follows (unlock, sudo, system auth, SSH signing, Quick Fill) — you must enroll at least one fingerprint first. The enrollment state machine (waiting / captured / processing / lift finger) matches the firmware fingerprint.h enum values.

Steps

  1. Settings → Fingerprint tab.
  2. Click "Enroll new fingerprint" and press the same finger repeatedly per the prompts until complete.
  3. Use "Rename" to change a name; use "Delete" to remove one.
ExpectedEnrollment shows live progress (capture count / lift-finger prompts); a new entry appears when done; rename is instant; a deleted fingerprint can no longer unlock/authorize.

Feature 3 · Keys & credentials management (incl. SSH key import / generation)

SSHAPITOTP/OTPSystemprereq for SSH/Quick Fill

DescriptionThe Keys tab supports four categories: System (login password), SSH/Git private keys, API credentials, OTP/TOTP secrets. Secrets are stored on-device and fingerprint-protected. Before testing Feature 7 (SSH agent) with ssh/git, you must import or generate an SSH key here first; before testing Feature 8 (Quick Fill), you must store an OTP entry here first.

Steps

  1. Settings → Keys tab, pick a category (System / SSH&Git / API / OTP).
  2. Import an SSH key: switch to the SSH/Git category, paste an OpenSSH-format private key (validated on import; encrypted keys are not supported), save.
  3. Generate on device: or click "Generate on device" — the device creates the key pair and the private key never leaves it; copy the public key afterwards for ~/.ssh/authorized_keys or GitHub.
  4. OTP: enter the TOTP secret (base32); API: enter a name and credential. Save and view in the list; rename or delete as needed.
ExpectedValid entries save and appear in the list, with the public key shown for SSH entries; an invalid SSH key (bad format / encrypted / unsupported type) shows a clear error and is not saved.

Feature 4 · Screen unlock

keyboard simneeds Accessibility

DescriptionTouchID-like lock-screen unlock. When the app detects the lock screen, the device sends an HMAC-signed fingerprint-match notification (0x21); on verification the app loads the password from Keychain and types it via CGEvent.

Steps

  1. Confirm the unlock password is set, Accessibility is granted, the device is connected, and a fingerprint is enrolled (Feature 2).
  2. Lock the screen (Ctrl+Cmd+Q).
  3. Touch an enrolled finger on the device sensor.
ExpectedThe app types your login password and Return, unlocking the screen. On a non-match nothing happens and no password is typed.

Feature 5 · sudo auth

PAMsudo_local

DescriptionReplace the sudo password prompt with a fingerprint. sudo triggers pam_immurok.so, which talks to the app over ~/.immurok/pam.sock; the app prompts for a fingerprint and replies OK on match.

Steps

  1. In Settings → Permissions, confirm "sudo auth" is enabled.
  2. Run sudo -k to clear the cache, then sudo true.
  3. Touch the device when prompted.
Expectedsudo succeeds on fingerprint match with no password typed. Disabling the toggle restores the default password prompt.
⚠️ macOS 13.x (Ventura) users: proper sudo support on macOS 13.x ships in the next version. The /etc/pam.d/sudo_local include mechanism was only introduced in macOS 14 (Sonoma) — 13.x does not auto-load sudo_local, so the line the installer writes has no effect. If you are on 13.x, enable sudo support manually:
  1. Confirm the PAM module is present: ls /usr/local/lib/pam/pam_immurok.so.
  2. Back up the original config: sudo cp /etc/pam.d/sudo /etc/pam.d/sudo.bak.
  3. Add this line to /etc/pam.d/sudo before the first auth rule (right after the leading comment line):
    auth     sufficient    /usr/local/lib/pam/pam_immurok.so
    e.g. sudo sed -i '' '1a\'$'\n''auth sufficient /usr/local/lib/pam/pam_immurok.so' /etc/pam.d/sudo
  4. Verify in a separate terminal window: sudo -k; sudo true (keep the current window open so you can restore with sudo cp /etc/pam.d/sudo.bak /etc/pam.d/sudo if anything breaks).
Once you upgrade to a version with 13.x support, remove this manually-added line and rely on the installer's automatic configuration.

Feature 6 · System auth dialog

PAM authorizationGUI dialog

Description"Enter your password to unlock" authorization dialogs in System Settings (e.g. changing a security setting) can use a fingerprint too, wired via /etc/pam.d/authorization.

Steps

  1. Confirm "System auth" is enabled.
  2. Open a System Settings pane that needs authorization (click a lock icon to unlock a setting).
  3. Touch the device when the authorization dialog appears.
ExpectedThe dialog is approved and closes, the setting unlocks.
Note: this project never touches authorizationdb — it integrates only via PAM authorization.

Feature 7 · SSH agent signing

ssh-agent protocolon-device signingrequires Feature 3

DescriptionThe app implements the SSH agent protocol and forwards signing requests to the device, which performs ECDSA signing with on-device keys — the private key never leaves the device. Prerequisite: an SSH key must already be imported or generated in Feature 3.

Steps

  1. Confirm an SSH key was imported or generated in Feature 3.
  2. In Settings → Permissions enable "SSH agent" and point SSH_AUTH_SOCK at the app's socket as instructed.
  3. Run ssh-add -l to list keys, then run an ssh or git push.
  4. Touch the device when a signature is requested.
Expectedssh-add -l lists the on-device public key; the connection / push completes after the device signs on fingerprint confirmation.

Feature 8 · Quick Fill OTP

default Ctrl+\customizable hotkey

DescriptionPress a global hotkey (default Ctrl+\, keyCode 42) in any field to pop a quick panel, search and pick an entry, and after fingerprint confirmation it auto-types the current TOTP code or the selected secret.

Steps

  1. First store at least one OTP entry (Feature 3).
  2. In a verification-code field on a website/app, press Ctrl+\.
  3. Search and select the target entry in the panel, then touch the device to confirm.
ExpectedThe panel filters by service name; after fingerprint confirmation the current 6-digit TOTP is typed at the cursor. The hotkey is configurable in Settings.
First-launch note: right after the first launch the global hotkey may not respond yet — re-set (or re-confirm) the hotkey in the app's settings, or restart the app, before it starts responding to Ctrl+\.

Feature 9 · imk CLI & agent command gate

CLIimk run --agent

Descriptionimk drives terminal workflows: list/read on-device secrets and inject env vars to run a subprocess. imk run --agent pops an approval overlay before the command runs, covering commands that wouldn't otherwise trigger PAM (e.g. git pull, npm install).

Steps

  1. Quick test: imk run --agent -- echo "hello world" — the overlay pops, touch the device, then hello world prints.
  2. List entries: imk list ssh / imk list otp / imk list api.
  3. Read a secret to stdout: imk get imk://api/<name>.
  4. Inject and run: imk run --env-file .env -- python deploy.py.
  5. Agent gate: imk run --agent -- git push origin main, touch the device when the overlay appears.
Expectedlist prints entry names; get prints the secret (trailing newline on an interactive TTY, raw bytes on a pipe/redirect); with --agent the command runs only after the app returns OK on a fingerprint match — closing the overlay or a 30s timeout returns REJECT and the command does not run.

Feature 10 · Install & test the imk skill in an AI agent

Claude Code pluginSKILL.mdfingerprint gate

DescriptionMake AI agents (Claude Code / Codex / Cursor / Cline …) automatically wrap sensitive commands (sudo, git push/ssh, reading secrets) with imk run --agent -- so a fingerprint approval gate pops up. The rules and decision tree live in the separate imk-skill repo (skills/using-imk/SKILL.md).

Install · Claude Codeinstall as a plugin

  1. Clone the skill repo into the plugins directory:
    git clone https://github.com/immurok/imk-skill ~/.claude/plugins/imk-tools
  2. Restart Claude Code (or reload plugins) so it picks up the using-imk skill.
  3. Confirm imk is on PATH: which imk should print /usr/local/bin/imk.

Install · other agentsCodex / Cursor / Cline, etc.

  1. Open skills/using-imk/SKILL.md in the imk-skill repo.
  2. Paste its contents into that agent's rules / instructions file (e.g. AGENTS.md, .cursorrules, Cline custom instructions).
  3. Save and have the agent re-read its rules.

Test the skill

  1. Make sure the app is running, the device is paired, and a fingerprint is enrolled.
  2. Verify the CLI gate directly: imk run --agent -- echo "hello world" — the overlay pops, touch the device, then hello world prints.
  3. In the agent chat, ask it to run a sensitive command (e.g. a git push or sudo systemctl restart api) and watch whether it automatically wraps it with imk run --agent -- before running.
  4. Touch the device to approve when the wrapped command runs.
ExpectedThe agent proactively wraps sensitive commands with imk run --agent --; a fingerprint gate appears before execution, the command proceeds only on a match, and is skipped on reject/timeout. Read-only commands (ls/cat/git log) and commands the user types manually are not wrapped.
Full decision tree, gotchas and install steps are in the imk-skill repo: github.com/immurok/imk-skill (skills/using-imk/SKILL.md).
